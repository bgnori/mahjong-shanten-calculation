# Leanシャンテン計算の高速化方針

**更新:** 2026-11-25

面子手の高速版は、**色別DPを基本とし、数牌の色内計算に牌種順DPを使う**方針とする。
実験的実装は[SuitDP.lean](../../Shanten/Experimental/SuitDP.lean)にある。
一般証明と性能目標の達成はまだ確認しておらず、既存の公開入口は切り替えていない。
[TileDP.lean](../../Shanten/Experimental/TileDP.lean)には、全牌種を一体で走査する
代替案Bも実験的に実装した。Aと牌種ごとの遷移を共有し、色別の表合成を行わない。
色の8・9と字牌では新しい順子を開始しないことで色境界をまたぐ順子を防ぐ。
Bも一般的な仕様一致は未証明である。
[PrunedSuitDP.lean](../../Shanten/Experimental/PrunedSuitDP.lean)では、
Cの枝刈りをAに組み合わせた上限付き色別DPも試す。完成形を深さ優先で列挙する
独立したCではない。
[IncrementalSuitDP.lean](../../Shanten/Experimental/IncrementalSuitDP.lean)は
上限を上げる際に色ごとの探索結果を再利用する実験版C′である。未証明。
作業範囲と完了条件は[現行計画](SHANTEN_LEAN4_PLAN.md)、
実測とその制約は[性能測定記録](SHANTEN_LEAN4_PERFORMANCE.md)を参照する。
Go実装は現在の対象外とする。

## 背景と維持する意味

既存の[容量付き一般探索](../../Shanten/Capacity/Search.lean)は、
完成候補を列挙する[探索](../../Shanten/MentsuHand/Search/BlockSearch.lean)を
固定牌込みの容量で絞り、最小不足枚数を求める。これは仕様一致を証明済みの
基準として維持する。候補の増加は性能上の懸念だが、測定だけで支配要因を確定しない。

高速版も完成目標までの不足枚数を最小化する。牌種 `i` の手元枚数を `h_i`、
固定牌の占有枚数を `f_i`、完成目標の手元部分を `t_i` とすると、
`t_i + f_i ≤ 4` を満たす完成目標に対する不足枚数は
`Σ_i max(t_i - h_i, 0)` である。固定面子が `F` 組なら、
手元部分の完成目標は `4 - F` 面子と1雀頭から構成する。
この不足枚数の最小値から1を引く既存の意味を維持し、13・14枚相当の両方を扱う。
14枚相当の完成値 `-1` と、未完成手に関する既存の面子手打牌選択保証も維持する。

固定牌に暗槓を含め、槓は4枚を占有する。見えている牌の残り枚数、役、振聴は考慮しない。
37種入力の検証と赤5の正規化は既存の境界で行い、DPは正規化済みの有効入力を対象とする。
固定面子がある場合の七対子・国士無双の適用除外を維持する。

## 色別DP

順子は同じ数牌の色内に限られ、刻子と雀頭も1牌種に限られる。
このため、萬子・筒子・索子・字牌に完成目標と不足枚数を分けられる。
各領域について、面子数 `m` と雀頭数 `p`（0または1）を指定し、
容量を満たす局所完成目標の最小不足枚数を求める。実現できない状態は明示的に区別する。

4領域の表を合成し、`Σ m = 4 - F`、`Σ p = 1` となる組合せの
不足枚数の和を最小化する。各領域で同じ `m, p` に対し最小値だけを残せるのは、
他の領域との組合せに必要な情報がその2つだけであり、不足枚数が加算されるためである。
この分解と最小値の保存は証明する。

### 数牌の牌種順DP

各色の1〜9を順に処理する。以下は状態と遷移の設計であり、最終的なデータ構造を
決めるものではない。

- `x_i` を牌種 `i` から始まる順子の本数、`y_i` を牌種 `i` の刻子の有無、
  `p_i` を牌種 `i` の雀頭の有無とする。同じ順子を複数選べる。
- `x_i` は0〜4、`y_i` と `p_i` は0または1。1牌種に2組以上の刻子を置くと
  4枚制限に反するため、刻子の有無で足りる。順子は1〜7からのみ開始する。
- 牌種 `i` の目標枚数は `t_i = x_i + x_{i-1} + x_{i-2} + 3*y_i + 2*p_i`。
  色の開始前の `x` と、8・9から始まる `x` は0とする。
- 状態は、処理済み位置、開始済み面子数、雀頭数、直前2位置の `x`、
  およびその状態に到達する最小不足枚数を持つ。遷移で `x_i, y_i, p_i` を選び、
  `t_i + f_i ≤ 4` を検査して `max(t_i - h_i, 0)` を加算する。
  面子数には新たに開始した順子と刻子を加え、雀頭数は1を超えない。
- 最後まで処理した状態から `m, p` ごとの最小値を取り出す。字牌は順子がないため、
  各牌種について刻子と雀頭の選択だけを合成する。

同じ状態への経路は最小不足枚数だけを残す。目標牌は手元にある牌だけに限定せず、
不足牌だけから構成される面子・雀頭も許す。四枚使い、重複順子、固定牌との競合、
完成目標の容量違反を取り違えないことが重要である。

## 証明と検証の方針

1. 各遷移が完成目標の部分構成と容量を表すこと、同じ状態の最小値を残しても
   後続の最適値が失われないことを示す。
2. 任意の有効な完成目標を色別・牌種順の選択に分解でき、逆に選択から有効な完成目標を
   構成できることを示す。雀頭・面子数と不足枚数の保存を含む。
3. 色別の最小値合成を完成目標全体の最小値に接続し、有効な13・14枚相当入力で
   既存の容量付き仕様と値が一致し、結果が存在することを証明する。
   既存の基準探索との値一致も導く。
4. 七対子・国士無双の既存計算を再利用し、3形と総合値、入力検証・正規化、
   面子手の打牌選択の既存保証を高速版に接続する。公開入口の切替えは保証を確認してから行う。
5. 四枚使い、重複順子、雀頭候補の競合、固定牌との容量競合、槓、完成・テンパイ・
   遠い手、および13・14枚相当の回帰例を検査する。基準探索が完了する入力では値を比較し、
   重い入力では独立に確認可能な期待値も使う。例の一致は一般証明の代わりにしない。

数値のみのDPで完成候補そのものを保持しない場合も、仕様一致に必要な存在証明と
既存の打牌選択保証を別途引き継ぐ。証明・実装・性能のどれか一つをもって
他の完了を主張しない。

## 性能評価と代替案

実装後、既存測定と実行方式・環境を揃え、起動を除く計算について基本100回の合計と
1回あたりの平均を測る。面子手だけでなく3形の計算も測定し、固定面子数・手牌の分布、
入力検証の範囲、時間切れとメモリを記録する。同一ケースの反復平均だけでは
牌譜全体の平均1ms以下の達成を判定しない。未達の場合は内訳を測り、設計を見直す。

代替案として、実験中の全牌種を一体で走査するDP、容量検査と下界に基づく枝刈り付き完成形探索、
色別結果の事前計算表がある。枝刈り付き色別DPは不足枚数の上限を0から増やし、
局所DPで上限を超える状態を捨てる。色の合成では、未処理の手元牌を全て利用できる
としても必要な牌が足りなければ、その不足を下界として枝を捨てる。
最初に完成目標が見つかった上限が最小不足枚数となること、および下界が安全なことは
一般証明が必要である。上限を繰り返すため、遠い手では遅くなる可能性がある。
実験版C′では、色内の状態を不足枚数順に処理し、上限を超える候補は保留する。
上限を上げたときは保留候補から再開し、確定した局所状態と最小値を再利用する。
色の合成は上限ごとにやり直す。保留候補の管理コストと再利用の正当性を別途評価する。
事前計算表は必要に応じた追加の高速化候補とし、
固定牌の残余容量をキーに反映すること、表の生成・正当性・メモリ・初期化を評価することを
前提とする。独立した枝刈り付き完成形探索と事前計算表は未実装であり、
性能達成を仮定しない。
